# Post-0.2.7 AI Packaging / Harness Trend Gaps (Agent Plugins & Aug 2026)

**Date:** 2026-08-19  
**Product context:** `bwai-cli@0.2.7` (`boilerplates-with-ai-skills`) — scaffolds runnable boilerplates with curated `SKILL.md` sets, SkillSpector gating, `skills.lock` provenance, optional Playwright MCP, and `bwai-delivery` workflows.  
**Baseline already shipped (≈ Aug 10, 2026):** Cursor `.cursor/skills` path fix; Playwright MCP on UI templates; `nextjs-ai-app`; `bwai-delivery` on all starters; SKILL.md enrichment / compliance gate. Prior landscape note: [`2026-08-10-llm-ai-boilerplate-trends.md`](./2026-08-10-llm-ai-boilerplate-trends.md).  
**Method:** Primary sources only (agent-plugins.org, Vercel Blog, Google Developers Blog, agentskills.io, modelcontextprotocol.io, Cursor / Claude / Codex / GitHub official docs). Secondary roundups were not used as evidence.

## Executive summary

The biggest packaging shift **not covered by the Aug 10 note** is **Agent Plugins 1.0.0** (public Aug 6, 2026): a vendor-neutral **directory + `plugin.json` contract** that co-locates **Agent Skills** and **MCP servers** so clients discover them the same way. It does **not** replace Skills or MCP; it standardizes the *box* those components travel in.

**Implication for bwai:** 0.2.7 already ships the *components* (skills under `.bwai/skills/` + agent mirrors; MCP as `.mcp.json` / `.cursor/mcp.json`). The gap is the **portable plugin package**: root `plugin.json`, fixed `skills/`, and a **closed, typed** Agent Plugins `mcp.json` (`$schema` + explicit `type` per server). Clients still keep native formats (Cursor `.cursor-plugin/`, Claude `.claude-plugin/`, Codex `.codex-plugin/`, Copilot root/`enabledPlugins`). bwai should **add a plugin export/scaffold layer**, not abandon per-agent skill mirroring.

Agent Plugins **intentionally omits** install, marketplace, permissions, sandboxing, and provenance. That omission is where bwai’s SkillSpector + `skills.lock` story remains a differentiator — package portably, **vet and pin** before ship.

**Do not re-do:** agentskills compliance gate, Playwright MCP templates, `nextjs-ai-app`, `bwai-delivery` defaults, Cursor skills path — those are done.

## What’s NEW since mid-August (esp. Agent Plugins)

### 1. Agent Plugins 1.0.0 — portable skills + MCP package (Aug 6, 2026)

**What it is**

- Open, vendor-neutral package format: a directory with required root `plugin.json` and optional fixed locations for components.
- v1 portable components: **Agent Skills** under `skills/` and **MCP servers** in root `mcp.json`.
- Reverse-domain **client extension** namespaces (manifest `extensions` + top-level dirs) for non-portable bits (hooks, agents, commands, etc.).
- Explicit non-goals: install sources/registries, enablement UX, permission/trust/sandbox policy, how skills are presented to models.

**Minimal layout**

```text
my-plugin/
├── plugin.json
├── skills/
│   └── summarize/
│       └── SKILL.md
├── mcp.json
└── com.example.client/   # optional client-owned
```

**Minimal manifest**

```json
{
  "$schema": "https://agent-plugins.org/schemas/1.0.0/plugin.schema.json",
  "name": "my-plugin"
}
```

Name rules: lowercase alphanumerics, hyphens, periods; 1–64 chars; no `--` / `..`.

**MCP shape (material for bwai)**

- Only path: root `mcp.json` (not inline in `plugin.json`, not alternate core paths).
- Top-level fields: `$schema` (`…/mcp.schema.json`) + `mcpServers` only.
- Each server **must declare `type`**: `stdio` | `streamable-http` | `sse` (sse optional for clients; deprecated HTTP+SSE).
- Failure isolation: bad MCP config disables MCP for that plugin but skills can still load; bad server entries skip independently.
- Subprocess env: clients launching stdio servers must provide `PLUGIN_ROOT` and `PLUGIN_DATA`.

**Launch clients (Vercel announce):** ChatGPT and Codex, Cursor, GitHub Copilot, Kiro, VS Code.  
**Google (same day):** joining TSC; Agents CLI + Data Agent Kit shipping plugins; advice: **don’t wrap a single skill or single MCP as a plugin** — use plugins when components **belong together and travel together**.

### 4. Adjacent Aug 2026 signals (packaging/security, not format)

- **Google ADK zero-trust agents (Aug 17, 2026):** when agents mutate production state, soft prompt/skill guardrails are insufficient — crypto write signatures, gVisor isolation, deterministic I/O gateways. Relevant to `nextjs-ai-app` / API starters as **guidance**, not a new package format.  
  https://developers.googleblog.com/build-zero-trust-ai-agents-with-googles-agent-development-kit/
- **Google Agent Plugins post** also names a layered ecosystem: find (Agentic Resource Discovery) → describe (AI Catalog) → package (Agent Plugins) → run (MCP + Skills). Discovery/catalog are separate adoptables; packaging does not obligate them.

## Implication for bwai (skills + MCP already separate)

```text
Today (0.2.7)
  .bwai/skills/*          → mirrored to agent skill dirs
  .mcp.json / .cursor/mcp.json
  skills.lock + SkillSpector
  bwai-delivery workflow

Missing interoperability floor
  plugin.json + skills/ + Agent Plugins mcp.json
  (optional com.<client>/ extensions)
```

1. **Compose, don’t replace.** Keep canonical `.bwai/skills/` and client mirrors for IDE day-one UX. Add a **plugin package** (export or scaffold dir) when a stack’s **skill set + MCP config should travel as one unit** (Google’s “belong together” test).
2. **Translate MCP shapes.** Project templates currently use inferred-transport shapes (e.g. Playwright `command`/`args` without `type` or `$schema`). Agent Plugins requires closed schema + explicit `type`. Emit portable `mcp.json` as a **generated artifact**; keep client-native files for local scaffold until clients fully map both.
3. **Own the omitted layer.** Market the catalog as: portable Agent Plugin packages **plus** SkillSpector scans and `skills.lock` pins — the trust/provenance Agent Plugins leaves to implementers.
4. **Avoid plugin spam.** Single-skill packages and “MCP-only for one client” should stay as skills / `.mcp.json`. Plugins are for **cohesive capability packs** (e.g. UI smoke: stack skill + Playwright MCP; AI app: `nextjs-ai-sdk` + tool MCP).
5. **Client extensions are optional overlays.** Prefer Agent Plugins core for portability; use Cursor/Claude/Codex/Copilot native plugin dirs only when hooks/agents/rules are required.
6. **Do not become a mega marketplace.** Cursor Marketplace, Copilot marketplaces, skills.sh already own discovery. bwai stays a **curated scaffold + vetted bundle** producer (consistent with Aug 10 P2-5).

## Prioritized backlog (net-new only)

### P0 — Changes what “good catalog entry” means after Agent Plugins 1.0

| ID | Enhancement | Why |
| --- | --- | --- |
| **P0-1** | **Agent Plugins package for each boilerplate (or export):** root `plugin.json` (`$schema` 1.0.0 + `name`/`version`/`description`), `skills/` snapshot of curated skills, portable `mcp.json` when the stack ships MCP | Clients now share a discovery floor ([agent-plugins.org](https://agent-plugins.org/), [Vercel](https://vercel.com/blog/introducing-agent-plugins)). |
| **P0-2** | **MCP translator:** generate Agent Plugins `mcp.json` with `$schema` + explicit `type: "stdio"` / `streamable-http` from existing template MCP configs (Playwright first) | Spec forbids transport inference ([agent-plugins MCP rules](https://agent-plugins.org/)). Current bwai `.mcp.json` is client-native. |
| **P0-3** | **Doctor / CI check:** if a plugin dir is present, validate `plugin.json` + matching `mcp.json` `$schema` versions; skill dirs still pass agentskills + SkillSpector | Conformance + existing security gate without inventing a scanner. |
| **P0-4** | **Docs positioning:** one paragraph in README/landing — “Skills + MCP inside; Agent Plugins when they ship together; SkillSpector/lock for trust” | Spec leaves trust empty ([Google](https://developers.googleblog.com/agent-plugins-package-your-skills-tools-and-more/), [portable vs client-owned](https://agent-plugins.org/)). |

### P1 — High leverage next

| ID | Enhancement | Why |
| --- | --- | --- |
| **P1-1** | `bwai export-plugin <boilerplate|project>` CLI (or `new --plugin`) writing a standalone Agent Plugins directory | Authors package once for Cursor/Copilot/Codex launch clients. |
| **P1-2** | Optional Copilot cloud wiring: `.github/copilot/settings.json` `enabledPlugins` pointing at repo-local or marketplace plugin | [About Copilot plugins](https://docs.github.com/en/copilot/concepts/agents/about-plugins). |

| **P1-5** | Map GetSuperpower / `bwai-delivery` as **skills inside the plugin**, not a second parallel install story | Skills remain the execution unit ([agentskills.io](https://agentskills.io/specification)). |

### P2 — Watch / opportunistic

| ID | Enhancement | Why |
| --- | --- | --- |
| **P2-1** | ARD / AI Catalog media type for plugins (Google’s find→describe→package stack) — **watch only** until a clear consumer | Named in [Google Agent Plugins post](https://developers.googleblog.com/agent-plugins-package-your-skills-tools-and-more/); not required to ship plugins. |
| **P2-2** | Zero-trust / ADK-style guidance skill for AI/API boilerplates (HITL, sandbox, signed writes) | [Aug 17 Google ADK post](https://developers.googleblog.com/build-zero-trust-ai-agents-with-googles-agent-development-kit/). |
| **P2-3** | MCP Apps / Tasks demos inside a plugin when a stack has a real long-running or UI tool need | [MCP 2026-07-28](https://blog.modelcontextprotocol.io/posts/2026-07-28/). |
| **P2-4** | Publish curated plugins to Cursor/Copilot marketplaces — only if distribution demand appears; stay curated | Avoid marketplace sprawl. |
| **P2-5** | Claude-native `.claude-plugin/` dual emit if Claude remains Agent Plugins–indirect | [Claude plugins](https://code.claude.com/docs/en/plugins). |

### Explicitly **not** recommended (repeats done work or anti-goals)

- Re-implementing SKILL.md compliance / Playwright MCP templates / `nextjs-ai-app` / `bwai-delivery` defaults / Cursor skills path.
- Replacing `.bwai/skills/` canonical storage with plugin-only installs.
- Building a general-purpose skill/plugin crawler or competing marketplace.
- Inventing a custom scanner instead of SkillSpector.
